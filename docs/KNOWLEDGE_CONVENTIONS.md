# 知识写作规范 · 跨通关 KJTONG 共享知识库

> 适用：所有向 `kjtong-kb-public` / `kjtong-kb-private` 写入内容的 AI Agent 与人工。

## 一、数据分级（写入前必须先判级）

| 级别 | 内容 | 存储位置 | 是否入 GitHub | 脱敏要求 |
|---|---|---|---|---|
| L1 公开 | 报关法规原文、HS 编码通则、编码约定、SKILL | `kjtong-kb-public` | ✅ 公开 | 无须，保留来源 URL + 日期 |
| L2 内部脱敏 | 运营 SOP、FAQ、客户索引卡、聚合统计 | `kjtong-kb-private` | ⚠️ 仅脱敏后 | 客户名→哈希 ID；金额→区间；联系人/地址/电话删除；原文→一句话摘要 |
| L3 受限 | 客户报关单原文、发票/箱单、个人信息 | 本机 `D:\kjtong-local\raw\` | ❌ 禁止 | 仅本机留存，不上传、不同步 |

**红线**：L3 数据任何形式都不得进入 GitHub（含 PEM、issue、PR 描述、commit message）。CI 的 `check-sensitive.sh` 会粗筛拦截。

## 二、法规原文写作规范
- 文件路径：`docs/regulations/YYYY-MM-DD-<主题>.md`，只增不改。
- 文件头必须含：来源平台（单一窗口/商务部等）、来源 URL、发布日期、生效日期、抓取时间。
- 发现错误不修改原文件，新增带日期的更正文件并在原文件加一行指向链接。
- 变更检测采用 SHA-256 比对 + 连续 2 次变更确认，防抓取抖动误报。

## 三、记忆写入规范
- 每条记忆带 `owner_agent_id`（来源客户端标识）。
- 讨论线程 ≠ 记忆：讨论内容只追加，不自动改写事实；结论必须显式写入并标注来源。
- 客户索引卡只存哈希 ID，不存可反推个人的信息。

## 四、引用规范
- 回答业务问题时附文件路径与出处段落，禁止无出处的结论。
- SKILL.md 使用 YAML frontmatter（`name` / `description`），供工具按需加载。
