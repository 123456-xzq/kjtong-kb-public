# 数据分级与脱敏规则（场景 3 落地版）

> 本文是 `AGENTS.md`「数据分级」一节的展开，供 AI Agent 与人工查阅；判断是否入库时以此表为准。

## 分级速查表

| 级别 | 典型内容 | 存储位置 | 入 GitHub | 脱敏规则 | 写入门禁 |
|---|---|---|---|---|---|
| **L1 公开** | 报关法规原文、HS 编码通则、编码约定、SKILL | `kjtong-kb-public` + 本机 Qdrant `local_docs` | ✅ 可公开 | 无须；保留来源 URL + 发布日期 + 生效日期 | 抓取器 PR + 人工确认 |
| **L2 内部脱敏** | 运营 SOP、FAQ、处理结论、客户索引卡、聚合统计 | `kjtong-kb-private` + 本机 Qdrant | ⚠️ 仅脱敏后 | 客户名→哈希 ID；金额→区间；联系人/地址/电话→删除；原文→一句话摘要 | 写入 Agent PR + 人工复核 |
| **L3 受限** | 客户报关单原文、发票、箱单、联系人、电话、地址、金额明细 | 仅本机 `D:\kjtong-local\raw\`（只读扫描，绝不入库） | ❌ 禁止 | 不适用（不出本机） | 本地索引器脱敏后只留路径引用 |

## 客户索引卡模板（L2 示例）

```markdown
## 索引卡 <哈希ID前8位>
- 问题类型：归类争议 / 单证不齐 / 退税异常（三选一）
- HS 类目：前 4 位（如 8517）
- 处理结论：一句话泛化描述（如"补充原产地证后放行"）
- 原文位置：本机路径引用 `D:\kjtong-local\raw\decl\2026\...`（不含原文内容）
- 写入 Agent：owner_agent_id
```
**禁止出现**：客户公司全称、联系人姓名、电话、详细地址、精确金额、订单号。

## 判定流程
1. 内容是否含客户可识别信息？→ 是：L3，禁止入库，只留本机。
2. 是否含聚合/泛化后仍可读的知识？→ 是：L2，脱敏后入私有仓库。
3. 是否为公开法规/通用约定？→ 是：L1，入公开仓库。
4. 拿不准 → 按更高级别处理（就高不就低）。

## 违规处理
- CI `check-sensitive.sh` 命中 → PR 阻断，人工复核后删除敏感内容重新提交。
- 一旦误入库：立即 `git filter-repo` 清除历史 + 联系 GitHub Support 清理缓存 + 通知法务评估。
